# 私人筆記（個人學習歸類）rules

適用：`source/_posts` 裡**新寫**的個人技術筆記——整理觀念、對照方案、寫給未來的自己（或同程度讀者），**不是**課堂講義、也不是舊文潤稿。

- 講義 → `lokitech-15day-lecture-rules`
- 舊文潤字／標題版本號 → `lokitech-post-polish`
- 共用 Hexo／協作底線 → 根目錄 `AGENTS.md`、`scaffolds/tagslang.md`

參考成品（口吻與章法）：`source/_posts/css-scope.md`。

## 這類文章是什麼

- **目的**：把學過或剛釐清的觀念收成可回查的筆記：痛點 → 機制 → 易混點 → 與其他方案怎麼選。
- **不是**：一步步跟著做的教學、講師備課備忘、15 天講義的「觀念／Demo／解析」三拍、也不是要交作業的教材。
- **讀者**：預設有基礎的自己；可用完整一點的 HTML／真實元件結構，但**專有名詞仍要講清楚**（不要假設一定知道 CSS Modules、Shadow DOM 等），也**不要把原生 API 寫得像某框架功能**。
- **深度**：寧願少章、每章講透，也不要名詞對照式帶過。開場就要讓人看出「這東西解決什麼情境」。

## 協作與終端

與 `AGENTS.md` 相同：不自動跑 `hexo`／`npm`／`pnpm`／`git push`；預覽用已開的 `http://localhost:4000`；改完給摘要，經同意再 commit（Conventional Commits、繁中、無 AI 署名）。

## Front matter 與檔名

- 用 `scaffolds/post.md` 慣例：封面、2～3 句導言、`<!-- more -->`（之前不放 Hexo 標籤）。
- 分類掛技術層（例如 `前端` > `HTML/CSS`）。若明確要藏進「私人」分類再用 `工具與其他` > `私人`，或 `hidden: true`。
- 檔名：`技術-主題` 或 `技術-版本-主題`（小寫、連字號），無日期前綴。
- `tag:` 只放技術名（無版本號）。標題以**用途／痛點**為主，不要只列 API 名（可對照 `css-scope` 標題寫法）。
- 標籤語法見 `scaffolds/tagslang.md`（`note` 必閉合、mermaid 用 NexT 標籤、站內 `{% post_link %}`）。

## 章節結構

- 一篇通常 **3～6 個 `#`**，由「為何需要」排到「怎麼選／支援度」；不要十幾個 `#` 並列。
- 每個 `#` 開頭用**一兩句說明本章在回答什麼**（可寫「本章只做…」「先講結論…」），不要空洞的「本章目標」。
- `#` 底下用 `##`／`###` 分層；**不跳層**。單一小節不要硬拆成只有一個子標題的空殼。
- 標題用清楚技術名詞或「問題句」（例如「同權重時誰贏」）；可口語一點，但仍要能掃 TOC 就懂。
- **固定收尾（私人筆記）**，接在主題大章之後：
  1. `# 瀏覽器支援`（若主題涉及 Web API／CSS 新語法；放 caniuse／版本線與官方連結）
  2. `# 專有名詞中英對照`（必有）：`- 中文術語（English term）` 條列，依出現順序，在與大章對應的 `##` 底下分組，不用表格
- **不要**講義那套：`# 回家作業`、`# 本篇重點回顧`、選讀標記、文末手寫上一篇／下一篇。
- 導言寫清閱讀順序（痛點 → 機制 → 易混點 → 對照 → 支援／名詞），方便回查。

## 內容章法（寫作模型）

1. **情境優勢要看得見**：開場用一份夠真實的 HTML（可稍複雜）＋錯誤寫法／正確寫法對照；必要時配色 mermaid 標出「誰被選中」。不要用假對立（例如明明 `.card img` 就夠、卻拿裸 `img` 嚇讀者）。
2. **先拆開、再組合**：易混的兩個東西（如 `:scope` vs `@scope`）先講**可獨立存在的純用法**，再接到合在一起的寫法。
3. **一個大章一個問題**：權重、proximity、命名隔離等不要拆成兩個看起來都像「權重」的 `#`；相關的收進同一層疊／對照章用 `##` 分。
4. **對照章要教名詞**：寫 BEM／Modules／Shadow DOM 時，先用 HTML／最短原生範例講「是什麼、屬哪一層（約定／建置／瀏覽器）」，再談與主題技術怎麼分工。
5. **收斂**：同一 DOM 情境不要重複貼三次長 HTML；後文用標註摘錄或「同開場 page.html」。圖只留有辨識度的（例如一張配色 DOM 圖＋必要流程圖）。

## 文體與格式

- 繁體中文；技術術語保留英文，重要的首次給短解釋。
- 用「你」可以，但口吻是**筆記／歸類**，不是「今天課堂會教…」。
- 一段一個重點、連貫書寫；並列短句用清單。**不用表格**（內文窄）。
- 行內碼只包真正的程式碼 token。**禁止粗體內放行內碼**（`` **`code`** ``／`` **…`code`…** ``），Hexo 會渲染異常——粗體與行內碼分開。
- 程式碼區塊：語言後接檔名；註解繁中；範例要能對上正文情境。
- mermaid：`{% mermaid … %}` … `{% endmermaid %}`；節點文字雙引號，換行 `<br/>`；需要標「選中／未選中」時用 `classDef` 配色。
- 說到 DevTools／瀏覽器行為時，寫可操作的觀察點（例如 Elements 裡的 `#shadow-root`）。

## 流程

1. 確認題目是私人筆記而非講義／潤稿；讀 `AGENTS.md` 與（若有）同主題舊文。
2. 先對齊：標題用途、開場情境 HTML、大章目錄（每章一句「在答什麼」），必要時先給 Loki 看目錄再寫。
3. 寫作中遇到易混概念，檢查是否「先純用、再組合」；對照其他方案時是否先解釋名詞。
4. 寫完自查：TOC 能否掃懂、有無假對立、有無粗體包行內碼、`note` 是否閉合、重複 HTML／圖是否可刪。
5. 預覽用 Loki 的 `localhost:4000`；可用 Chrome DevTools 看 TOC、console、mermaid 是否渲染。不自動建置。
